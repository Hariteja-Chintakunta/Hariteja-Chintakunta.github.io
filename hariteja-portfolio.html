playwright-capstone ↗

Playwright + TypeScript · AutomationExercise · The flagship framework
18 RUN · 1 SKIPPED · 0 HIDDEN

A complete e-commerce framework: registration, login/logout, search and cart, checkout with invoice download, and contact-form upload — then the parts most portfolios skip: axe-core accessibility scans, visual-regression baselines, and 5 network-mocking tests that intercept, stub and throttle real requests. Custom fixtures inject 8 page objects into every test and block ad/tracking requests, because ad overlays on the demo site were causing flaky clicks — the fix is in the fixture, not in a sleep.

restassured-capstone ↗

REST Assured + Java + TestNG · GoRest API · The API starter, honestly labelled
3 TESTS · CHAINED

A small, clean API suite with one idea done properly: chaining. Test 1 lists posts and saves the first post’s ID and title; test 2 fetches exactly that post and verifies the fields match; test 3 searches by the title’s first word and checks the original post is in the results. Environment switches with one flag — -Denv=uat — and every response is held to a 5-second budget.

How I work

Rules a team can rely on

01

One test, one job

If a test checks three things, its failure tells you nothing. Each test owns one behaviour and one clear failure message.

02

No sleeps, ever

Flakiness is a bug in the test, not a reason to wait longer. Fix the cause — like the ad overlays — in the fixture.

03

A failure must explain itself

Traces, screenshots and reports on failure, every time — including one failure I keep on purpose to prove it.

04

Honest numbers

Counts come from the code. Starters are called starters. A report earns trust when it says what it isn’t.
